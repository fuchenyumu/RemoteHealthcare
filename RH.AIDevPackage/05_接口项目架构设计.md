# RH.WebApi .NET8 解决方案架构设计

## 1. 架构概述

`RH.WebApi`基于 PurestAdmin 的 .NET8 版本改造，结合 SqlSugar + PostgreSQL 16，实现系统管理与远程会诊业务的统一后端。整体遵循模块化、领域分层、依赖倒置原则，核心特性如下：

- **模块化**：PurestAdmin 原生模块 + 远程会诊业务扩展模块
- **统一数据访问**：SqlSugar 5.1.4 对接 `admin-postgresql.sql` 与 `purest_rc_business.sql`
- **接口风格**：RESTful API，遵循 `/api/{aggregate}/{action}` 约定
- **跨模块通信**：事件总线（`PurestAdmin.Multiplex`）与工作流（`PurestAdmin.Workflow`）

## 3. 模块职责与依赖

| 模块 | 关键职责 | 备注 |
| --- | --- | --- |
| `PurestAdmin.Api.Host` | 启动配置、终端路由、Swagger、安全中间件 | 与前端 `RH.Admin` 对接 |
| `PurestAdmin.Application` | 应用服务、DTO、权限标识 | 新增 `RemoteConsultation` 目录承载业务服务 |
| `PurestAdmin.Core` | 基础实体、领域服务、常量定义 | 复用账号、组织等基础模型 |
| `PurestAdmin.SqlSugar` | SqlSugar 配置、实体映射、仓储实现 | 新增业务实体映射 (`Entities/RemoteConsultation`) |
| `PurestAdmin.Zero` | RBAC、字典、日志、配置中心 | 直接复用，不改动 |
| `PurestAdmin.Multiplex(.Contracts)` | 事件发布/订阅、集成消息 | 会诊流程通知、审计日志扩展 |
| `PurestAdmin.Workflow` | 工作流定义、审批流 | 可用于会诊审核节点 |
| `PurestAdmin.BackgroundService` | Quartz/HostedService | 同步任务、资料打包定时清理 |

## 4. SqlSugar 数据访问规范

### 4.1 连接与多租配置

```csharp
builder.Services.AddSqlSugarClient(options =>
{
    options.ConnectionString = builder.Configuration.GetConnectionString("AdminDb");
    options.DbType = DbType.PostgreSQL;
    options.IsAutoCloseConnection = true;
    options.ConfigureExternalServices = new ConfigureExternalServices
    {
        EntityNameService = (type, entity) =>
        {
            if (type.Namespace?.Contains("RemoteConsultation") == true)
            {
                entity.DbTableName = "purest_rc_" + entity.DbTableName;
            }
        }
    };
});
```

### 4.2 实体定义示例

```csharp
using SqlSugar;

[SugarTable("purest_rc_consultation")]
public class RcConsultationEntity : AuditEntity
{
    [SugarColumn(IsPrimaryKey = true, IsIdentity = false)]
    public long Id { get; set; }

    public long CaseId { get; set; }
    public long? PackId { get; set; }
    public long ApplyOrgId { get; set; }
    public long ApplyDoctorId { get; set; }
    public string ConsultationStatus { get; set; } = default!;
    public string EmergencyLevel { get; set; } = default!;
    public DateTime? ScheduledStartTime { get; set; }
    public DateTime? ScheduledEndTime { get; set; }
}
```

> `AuditEntity` 为基础审计字段封装（`CreateBy/CreateTime/UpdateBy/UpdateTime/Remark`）。

业务服务通过 `IRemoteConsultationAppService` 暴露接口，在 API 层注入使用。权限依托 `PurestAdmin.Zero` 的菜单/功能配置：

```csharp
[Authorize("rc:consultation:manage")]
public class RemoteConsultationAppService : ApplicationService, IRemoteConsultationAppService
{
    private readonly IRcConsultationRepository _repository;

    public async Task<PageResult<RcConsultationDto>> GetPagedAsync(QueryConsultationInput input)
    {
        var query = _repository.QueryBuilder
            .Where(c => c.ConsultationStatus == input.Status || input.Status == null)
            .WhereIF(input.ApplyDoctorId.HasValue, c => c.ApplyDoctorId == input.ApplyDoctorId);

        return await query.ToPageAsync<RcConsultationDto>(input.PageIndex, input.PageSize);
    }
}
```

## 6. API 宿主与中间件

`Program.cs` 中统一注册：

```csharp
var builder = WebApplication.CreateBuilder(args);

builder.Services
    .AddControllers()
    .AddJsonOptions(opt =>
    {
        opt.JsonSerializerOptions.Converters.Add(new DateTimeConverter());
    });

builder.Services.AddCorsPolicy();
builder.Services.AddAuthenticationJwt(builder.Configuration);
builder.Services.AddAuthorizationWithPolicies();
builder.Services.AddSqlSugarClient(...);
builder.Services.AddApplicationServices();

var app = builder.Build();

app.UseRequestLogging();
app.UseCors("AllowAll");
app.UseAuthentication();
app.UseAuthorization();
app.MapControllers();
app.MapHealthChecks("/health");

app.Run();
```

### 中间件管线

- `UseRequestLogging`：集成 Serilog/NLog
- `UseExceptionHandling`（自定义）：捕获业务异常返回统一结构
- `UseSqlSugarUnitOfWork`：过滤器方式管理事务
- `UseSecurityHeaders`：医疗数据安全要求（X-Content-Type-Options、HSTS等）

## 7. 远程会诊业务流程实现

### 7.1 审核与排期

- 提交申请：`POST /api/rc/consultation`，写入 `purest_rc_consultation`
- 审核：`PUT /api/rc/consultation/{id}/audit`，变更状态并追加 `Timeline`
- 排期：`PUT /api/rc/consultation/{id}/schedule`，同步会议时间、RTC房间

审批过程可选用 `PurestAdmin.Workflow`：

```csharp
await _workflowService.StartAsync(new StartWorkflowInput
{
    WorkflowCode = "RC_CONSULT_AUDIT",
    BusinessId = consultation.Id.ToString(),
    Initiator = CurrentUser.Id,
    Variables = new { Emergency = consultation.EmergencyLevel }
});
```

### 7.2 会诊中协同

- RTC 参数存储在 `purest_rc_consultation` (`rtc_channel_id`, `meeting_room_no`)
- 成员邀请：写入 `purest_rc_consultation_member` 并通过 `PurestAdmin.Multiplex` 发送站内信/短信

### 7.3 报告签署与归档

- 报告草稿：`POST /api/rc/report`
- 电子签名：上传签名文件到 `purest_file_record`，在报告表中引用
- 归档完成后触发 `purest_rc_sync_task`（任务类型 `REPORT`）同步至院内 EMR

## 8. 后台任务与集成

`PurestAdmin.BackgroundService` 中新增远程会诊相关任务：

- **资料打包清理**：定时检查 `purest_rc_patient_pack` 过期记录，释放存储
- **同步任务重试**：轮询 `purest_rc_sync_task` 状态为 `FAILED` 的记录，重新推送

示例：

```csharp
public class RcSyncRetryJob : IHostedService
{
    private readonly ISchedulerFactory _schedulerFactory;

    public Task StartAsync(CancellationToken cancellationToken)
    {
        var scheduler = _schedulerFactory.GetScheduler(cancellationToken).Result;
        var job = JobBuilder.Create<RcSyncRetryQuartzJob>().WithIdentity("RcSyncRetry").Build();
        var trigger = TriggerBuilder.Create()
            .WithCronSchedule("0 */10 * * * ?")
            .Build();
        return scheduler.ScheduleJob(job, trigger, cancellationToken);
    }
}
```

## 10. 测试与发布

- **单元测试**：在 `PurestAdmin.Application` 中使用 `xUnit + NSubstitute` 校验应用服务逻辑
- **集成测试**：引入 `WebApplicationFactory<PurestAdmin.Api.Host.Program>` 构建内存宿主
- **API 文档**：`Swashbuckle` 显示远程会诊模块，使用分组 `v1`、`Rc` 标记
- **部署**：Docker 镜像以 `PurestAdmin.Api.Host` 为入口，Kubernetes 使用 ConfigMap/Secret 注入配置

## 11. 与前端的契约

- 前端 `RH.Admin` 通过 `/api/rc/*` 接口调用，所有接口返回统一响应：

```json
{
  "success": true,
  "data": {},
  "error": null,
  "traceId": "..."
}
```

- 权限编码与菜单在 `purest_function`、`purest_function_interface` 中配置，与前端按钮 `v-auth` 指令联动
- 字典数据（患者类型、会诊状态等）统一来源于 `purest_dict_category` / `purest_dict_data`
