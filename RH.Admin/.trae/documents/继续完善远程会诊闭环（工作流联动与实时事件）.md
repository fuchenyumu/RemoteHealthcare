## 工作内容概览
1. 将会诊与工作流强绑定（创建即启动、审核即推进、详情可查看实例）
2. 集成 SignalR 实时事件订阅（会诊状态、成员、报告签署等提示与数据刷新）
3. 扩展资料包附件元数据（影像类型/来源系统）并优化会诊中影像浏览入口
4. 新增远程会诊数据看板（统计卡片 + 趋势/分布图表），路由与权限接入
5. 完善安全与合规提示、录制开关与角色权限控制
6. 全量验证用例与交互回归

## 1. 工作流联动改造
- 创建会诊 → 启动实例：
  - 在 `createConsultation` 成功回调中调用 `startWorkflow(definitionId, { businessId: consultationId, title, emergencyLevel, applyDoctorId })`。
  - 后端返回 `instanceId` 写入会诊记录或由前端暂存；详情页显示实例号与“查看工作流实例”按钮（跳转到工作流实例详情）。
- 审核推进：
  - 审核弹窗提交时，除了 `auditConsultation`，同时调用 `auditingWorkflow(instanceId, { approved, comment })`，由后端推进节点并产生日志。
- 轨迹展示：
  - 复用会诊“流程轨迹”页签，将工作流事件统一写入 `timeline` 接口；前端不分来源，按事件时间/操作者展示。
- 设计模板：
  - 使用已有设计器定义模板：开始 → 科室审核 → 医务科审核 → 排期 → 会诊 → 报告签署 → 结束；为审批节点配置审批人来源（组织/角色）。

## 2. SignalR 实时事件订阅
- 连接与频道：
  - 使用 `createConnection('/consultation')` 建立连接；或每个会诊详情页连接到 `'/consultation/' + consultationId` 子频道。
- 事件类型与前端处理：
  - `ConsultationStatusChanged`：更新当前详情状态与列表刷新；弹出 `ElMessage` 提示。
  - `MemberJoined/MemberLeft`：刷新成员列表；在演示页右侧显示在线成员数。
  - `ReportSigned`：刷新报告页签；提示签署成功。
  - `AttachmentAdded/Deleted`：刷新附件列表。
- 生命周期：
  - 打开会诊详情抽屉时订阅，关闭或路由离开时 `connection.stop()`。

## 3. 资料包附件元数据扩展
- 上传前端：
  - 在 `uploadPatientPackFile` 前增加元数据选择（影像类型：`CT/MRI/US/CR/DOC`；来源系统：`HIS/LIS/PACS/EMR/其他`）。
  - 将元数据与文件一同上传（表单字段如 `imageType/sourceSystem`）。
- 展示优化：
  - 在资料包详情与会诊附件页签，按类型分组/筛选；影像显示入口预留“打开影像（DICOM）”按钮（静态）。

## 4. 远程会诊数据看板
- 路由与权限：
  - 新增 `'/remote/dashboard'`，权限码 `remote.dashboard`。
- 页面内容：
  - 统计卡片：会诊总数、今日会诊、待审核、已完成（`ReCountTo` + `ElCard`）。
  - 图表：
    - 趋势折线图（近30天会诊量）。
    - 科室分布饼图。
    - 月度完成柱状图。
  - 数据来源：后端统计接口或临时聚合 RC 模块分页数据。

## 5. 安全与合规完善
- 患者隐私提示：
  - 在会诊详情与演示页顶部显示隐私与信息收集提示文本。
- 录制开关：
  - 在演示页提供“录制（演示占位）”开关，默认关闭，仅 `Admin`/主持人可见；真实录制交由后端策略管控。
- 角色权限：
  - 进入演示页权限：主持人/专家；观察员仅查看无控制栏。
  - 使用现有权限码与成员角色字典组合控制按钮显示。

## 6. 验证与测试
- 用例覆盖：
  - 正常闭环：申请→审核通过→排期→开始→签署→结束。
  - 异常分支：审核驳回、关闭会诊、紧急会诊快速排期。
  - 实时事件：在两个浏览器会诊详情同时打开，执行审核/签署操作，另端收到事件并更新。
- 路由串联：
  - 患者详情→资料包（caseId 预填）；会诊详情→演示页；演示页返回会诊列表。
- 角色校验：
  - 不同角色下按钮/功能可见性验证。

## 后端/契约补充建议（为前端改动提供支撑）
- 工作流实例：`startWorkflow(definitionId, payload) -> { instanceId }`，并在会诊详情返回 `instanceId` 字段。
- 审核推进：`auditingWorkflow(instanceId, { approved, comment })` 成功后落地事件到 `timeline`。
- SignalR 事件：推送通道与事件名固定，载荷包含 `consultationId`、`type`、`payload`、`timestamp`。
- 附件上传：支持 `multipart/form-data` 附带 `imageType/sourceSystem` 字段；附件列表返回元数据。
- 统计接口：会诊量/状态分布/科室分布/月度完成聚合。

## 里程碑与产出
- M1：工作流启动与推进打通；会诊详情显示实例与轨迹统一。
- M2：SignalR 事件订阅与提示；成员/状态/报告列表可实时刷新。
- M3：资料包附件元数据与筛选；会诊附件页签分组展示。
- M4：数据看板与权限；可视化统计上线。
- M5：安全与合规提示与录制开关；角色控制完善。

## 风险与规避
- 工作流与会诊ID映射：确保唯一且可查询，避免多实例绑定同一会诊。
- 实时订阅性能：对高并发会诊使用按需订阅与断开策略；避免在列表页批量订阅。
- 元数据一致性：前后端字段命名与字典值对齐；上传后立即刷新以免统计失真。

## 验证方式
- 本地联调与双端浏览器实时验证（SignalR）。
- 路由与权限手工测试 + 基本单元测试（类型与字典映射）。
- 数据看板与统计数值与后台报表比对。
